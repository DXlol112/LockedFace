# Модуль `def_collection.py`

## Назначение модуля

`script/core/monitoring/def_collection.py` реализует рабочий поток LockedFace.
Он открывает камеру, запускает MediaPipe Face Mesh, проверяет состояние
пользователя, показывает выбранное предупреждающее медиа и отправляет кадры в
главный UI-поток.

## Место в архитектуре

`MainPage._start_video_process()` создаёт `VideoThread`, подключает два сигнала
и запускает его через `QThread.start()`.

```text
MainPage (главный поток Qt)
    → VideoThread.start()
        → VideoThread.run() (рабочий поток)
        ├── change_pixmap_signal(frame) → MainPage.update_video_image()
        └── finished_signal()           → MainPage.on_video_finished()
```

Модуль объединяет orchestration. Математические проверки и временное состояние
вынесены в `monitoring/settings`.

## Зависимости и настройка окружения

- OpenCV читает камеру, видеокадры, изображения и создаёт окно `Error`;
- MediaPipe Face Mesh возвращает лицевые landmarks;
- ffpyplayer воспроизводит звуковую дорожку видео;
- NumPy используется в типе Qt-сигнала кадра;
- `tempfile` и `shutil` создают временную копию пользовательского медиа;
- `time` предоставляет время сессии, синхронизацию и задержку паузы.

При импорте устанавливаются:

| Переменная | Значение | Назначение |
| --- | --- | --- |
| `QT_XCB_GL_INTEGRATION` | `none` | Отключение Qt/OpenGL-интеграции |
| `QT_DEBUG_PLUGINS` | `0` | Отключение подробного debug плагинов Qt |
| `TF_CPP_MIN_LOG_LEVEL` | `3` | Подавление сообщений TensorFlow backend |

Импорт Face Mesh сначала пробует `mediapipe.solutions.face_mesh`, затем
`mediapipe.python.solutions.face_mesh`. Если оба варианта недоступны, модуль
завершает процесс через `sys.exit()`.

## Справочник функций

### `get_safe_path(orig_path)`

Создаёт временную копию выбранного медиа с тем же расширением.

**Параметры:** `orig_path` — строкоподобный путь; аннотация типа отсутствует.

**Возвращаемое значение:**

- строковый путь временного файла;
- `None`, если путь пуст или исходный файл не существует.

**Алгоритм:** извлекает расширение, создаёт файл через `mkstemp()`, закрывает
низкоуровневый descriptor и копирует содержимое с метаданными через `copy2()`.

**Побочные эффекты:** создаёт файл в системном временном каталоге.

**Исключения:** ошибки создания и копирования не перехватываются. Если
`copy2()` завершится ошибкой после `mkstemp()`, пустой временный файл может
остаться.

**Назначение копии:** предупреждающий плеер работает не с управляемым файлом
напрямую, а с временной копией, которую поток удаляет при завершении.

## Класс `VideoThread`

`VideoThread(QThread)` инкапсулирует одну сессию мониторинга.

### Сигналы

| Сигнал | Payload | Назначение |
| --- | --- | --- |
| `change_pixmap_signal` | `np.ndarray` | Передать очередной кадр камеры в UI |
| `finished_signal` | отсутствует | Сообщить о завершении и очистке ресурсов |

Сигналы объявлены атрибутами класса, как требует PyQt.

### Состояние экземпляра

| Атрибут | Назначение |
| --- | --- |
| `file` | Путь выбранного предупреждающего медиа |
| `gaze` | Включена ли проверка глаз |
| `glasses_enabled` | Использовать ли порог для очков |
| `work_time` | Длительность активной сессии в секундах |
| `sensitivity` | Неизменяемые пороги распознавания |
| `timer_settings` | Неизменяемые задержки мониторинга |
| `_run_flag` | Должен ли продолжаться цикл |
| `is_paused` | Находится ли поток в режиме паузы |

## Справочник методов

### `__init__(file, gaze, glasses_enabled, work_time, sensitivity=DEFAULT_SENSITIVITY, timer_settings=DEFAULT_TIMER_SETTINGS)`

Сохраняет параметры сессии и задаёт начальное состояние управления.

**Параметры:**

- `file` — путь медиа;
- `gaze` — флаг проверки глаз;
- `glasses_enabled` — выбор порога глаз;
- `work_time` — рабочее время в секундах;
- `sensitivity` — `SensitivitySettings`;
- `timer_settings` — `TimerSettings`.

**Изменение состояния:** устанавливает `_run_flag = True` и
`is_paused = False`.

**Побочные эффекты:** кроме инициализации `QThread` отсутствуют. Камера и файл
ещё не открываются.

**Важные условия:** первые четыре параметра не имеют аннотаций и не
валидируются. Defaults настроек безопасно разделяются благодаря frozen-
dataclasses.

### `run()`

Главный метод рабочего потока. Qt вызывает его после `start()`; напрямую из UI
его вызывать не следует.

**Подготовка:**

1. возвращает `_run_flag` в `True`;
2. создаёт временную копию `file`;
3. открывает камеру `cv2.VideoCapture(0)`;
4. создаёт FaceMesh для одного лица с `refine_landmarks=True`;
5. подставляет оба confidence из `SensitivitySettings`;
6. инициализирует плееры, состояние окна и `MonitoringTimers`.

**Основной цикл:** выполняется, пока камера открыта и `_run_flag` равен `True`.

#### Режим паузы

- при первом paused-кадре вызывает `timers.begin_pause()`;
- ставит активный ffpyplayer на паузу;
- продолжает читать камеру;
- рисует красный текст `PAUSE` и отправляет кадр в UI;
- спит `pause_frame_delay` и пропускает распознавание и проверку рабочего
  времени.

После продолжения поток вызывает `timers.end_pause()` и снимает паузу с
плеера. Завершённая длительность паузы исключается из рабочего времени.

#### Анализ активного кадра

1. читает кадр и завершает цикл при ошибке;
2. проверяет окончание `work_time`;
3. преобразует BGR в RGB;
4. вызывает `face_mesh.process()`;
5. получает `(DetectionStatus, landmarks)` через `run_detection_checks()`;
6. рисует четыре зелёные точки глаз при наличии лица;
7. передаёт статус в `timers.should_show_alert()`.

#### Запуск предупреждения

При первом `should_error == True` поток выбирает обработчик медиа:

- `.jpg`, `.jpeg`, `.png` считаются статичными изображениями;
- остальные расширения сначала открываются как видео одновременно через
  ffpyplayer и OpenCV;
- если OpenCV не открыл видео, плеер закрывается, а дальнейшая ветка пытается
  читать файл как изображение.

Для видео OpenCV читает и циклически перематывает кадры, а ffpyplayer
продвигает аудио. Значение времени от плеера сравнивается с позицией OpenCV и
при необходимости используется `sleep()` для синхронизации. Кадр показывается
в нативном окне OpenCV `Error`.

Для изображения файл читается через `cv2.imread()` и показывается в том же
окне. Чтение выполняется заново на каждой итерации активного предупреждения.

Если временной копии нет, поток выводит сообщение и переходит к следующей
итерации.

#### Закрытие предупреждения

Когда `should_error` становится `False`, а окно активно, поток:

1. закрывает ffpyplayer;
2. освобождает `error_cap`;
3. уничтожает окно `Error`;
4. сбрасывает `error_window_active`;
5. запускает общий cooldown.

Независимо от предупреждения очередной кадр камеры отправляется через
`change_pixmap_signal`, а `cv2.waitKey(1)` обслуживает окна OpenCV.

**Завершение и очистка:** блок `finally` закрывает плееры, освобождает камеру,
уничтожает все окна OpenCV, пытается удалить временный файл и отправляет
`finished_signal`.

**Побочные эффекты:** работает с камерой, временным каталогом, окнами OpenCV,
аудиоустройством, CPU/GPU backend MediaPipe и Qt-сигналами; выводит некоторые
сообщения в stdout.

**Исключения:** большинство ошибок основного цикла не перехватываются, но
ресурсы из блока `finally` очищаются. Ошибки до входа в `try`, включая
`get_safe_path()` и создание FaceMesh, могут завершить метод без
`finished_signal` и общей очистки. Ошибки отдельных операций плеера частично
перехватываются и печатаются.

### `stop()`

Устанавливает `_run_flag = False` и синхронно вызывает `wait()`.

**Возвращаемое значение:** отсутствует.

**Побочные эффекты:** вызывающий поток блокируется до полного завершения
`run()` и очистки ресурсов.

**Важные условия:** UI вызывает метод из главного потока. Вызов из самого
`VideoThread` привёл бы к ожиданию самого себя.

### `toggle_pause()`

Инвертирует `is_paused`.

**Возвращаемое значение:** отсутствует.

**Побочные эффекты:** только изменение флага. Фактическая пауза таймеров и
плеера применяется на следующей итерации `run()`.

**Важные условия:** доступ к boolean не защищён lock; текущая реализация
рассчитывает на простое управление из UI-потока.

## Полный поток ресурсов

```text
selected managed media
    → get_safe_path()
    → temporary copy
    → image branch OR ffpyplayer + cv2.VideoCapture
    → warning ends / thread stops
    → close players
    → destroy OpenCV windows
    → remove temporary copy
    → finished_signal
```

## Как расширять рабочий поток

### Добавить сигнал

1. Объявите `pyqtSignal` атрибутом класса с точным payload-типом.
2. Отправляйте только данные, безопасные для queued connection.
3. Подключите slot в `MainPage` до `thread.start()`.
4. Не изменяйте Qt-виджеты непосредственно из `run()`.

### Добавить формат медиа

Определите, является формат статичным или потоковым, затем согласованно
обновите ветвление `run()`, фильтр `FilePage` и превью `FileCard`. Добавьте
явное освобождение нового ресурса в обычную ветку закрытия и `finally`.

### Добавить новую проверку

Реализуйте её в `monitoring_checks.py`, добавьте пороги в
`SensitivitySettings` и временную политику в `MonitoringTimers`. В `run()`
должна остаться только orchestration.

### Выбор камеры

Добавьте индекс или URL камеры параметром конструктора, провалидируйте его в
UI и используйте вместо литерала `0`.

## Текущие ограничения

- Камера зафиксирована на индексе `0`.
- Большой `run()` объединяет распознавание, playback, окна и очистку.
- Статичными явно считаются только `jpg`, `jpeg` и `png`.
- Изображение повторно декодируется на каждом кадре предупреждения.
- OpenCV и ffpyplayer синхронизируются вручную через `sleep()`.
- Некоторые исключения подавляются bare `except`, а сообщения идут через
  `print` вместо настроенного logger.
- `stop()` может ненадолго блокировать главный UI-поток.
- FaceMesh не закрывается явно через context manager.
- Ошибка подготовки до блока `try` не гарантирует `finished_signal`.
