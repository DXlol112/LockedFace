# Модуль `config.py`

## Назначение модуля

`script/core/config.py` предоставляет единый интерфейс чтения и записи
пользовательской конфигурации LockedFace. UI не открывает JSON-файл напрямую,
а использует `load_config()`, `save_config()` и `update_config()`.

## Место в архитектуре

Путь к файлу предоставляет `get_config_path()` из `path_utils.py`. Конфигурация
хранится в пользовательском каталоге данных и не входит в one-folder сборку.

```text
UI → load_config/update_config → get_config_path → data_dir/config.json
```

## Зависимости

- `json` преобразует Python-словарь в JSON и обратно;
- `logging` сообщает о повреждённом или недоступном файле;
- `copy.deepcopy` создаёт независимую копию вложенных значений по умолчанию;
- `typing.Any` допускает значения разных JSON-совместимых типов;
- `get_config_path()` определяет фактический путь хранения.

## Константа `DEFAULT_CONFIG`

`DEFAULT_CONFIG: dict[str, Any]` содержит базовую схему текущих настроек:

| Секция | Ключ | Значение по умолчанию | Назначение |
| --- | --- | --- | --- |
| `user_settings` | `selected_file` | `None` | Путь выбранного управляемого медиа |
| `user_settings` | `work_time_seconds` | `0` | Длительность сессии в секундах |
| `user_settings` | `translations_select` | `"RU"` | Текущий язык интерфейса |
| `monitoring_settings` | `gaze_enabled` | `False` | Включение проверки глаз |
| `monitoring_settings` | `glasses_enabled` | `False` | Использование порога для очков |

Каждый вызов `load_config()` начинает с глубокой копии этого словаря.

## Справочник функций

### `load_config() -> dict[str, Any]`

Возвращает полную конфигурацию, объединяя значения по умолчанию с содержимым
`config.json`.

**Параметры:** отсутствуют.

**Возвращаемое значение:** новый словарь. Значения сохранённого JSON
объединяются со значениями по умолчанию внутри каждой секции. Поэтому
отсутствующий ключ секции по-прежнему получает безопасное значение.

**Побочные эффекты:** получает путь через `get_config_path()`, что может создать
каталог данных; при наличии файла читает его в UTF-8.

**Обработка ошибок:** `JSONDecodeError` и `OSError` перехватываются, записываются
как warning, после чего возвращаются defaults. JSON другого верхнеуровневого
типа также игнорируется с warning.

**Важные условия:** типы отдельных ключей не проверяются. Неизвестные ключи
сохраняются в возвращаемом словаре.

### `save_config(config: dict[str, Any]) -> None`

Полностью перезаписывает `config.json` переданным словарём.

**Параметры:**

- `config` — словарь с JSON-сериализуемыми ключами и значениями.

**Возвращаемое значение:** отсутствует.

**Побочные эффекты:** открывает файл в режиме `w`, кодировке UTF-8 и вызывает
`json.dump()` с отступом четыре пробела и `ensure_ascii=False`.

**Исключения:** ошибки файловой системы и сериализации не перехватываются и
передаются вызывающему коду.

**Важные условия:** функция не добавляет отсутствующие defaults. Для частичного
изменения предназначена `update_config()`.

### `update_config(section: str, **values: Any) -> dict[str, Any]`

Читает текущую конфигурацию, обновляет именованные значения выбранной секции и
сохраняет результат, не заменяя остальные значения этой секции.

**Параметры:** имя `section` и произвольные пары `key=value`.

**Возвращаемое значение:** итоговый сохранённый словарь.

**Побочные эффекты:** выполняет полный цикл чтения и полной перезаписи файла.

**Исключения:** ошибки `save_config()` не перехватываются.

**Важные условия:** имена секции и ключа не сверяются с `DEFAULT_CONFIG`.
Опечатка создаст новую секцию или новый вложенный JSON-ключ.

## Поток данных

```text
update_config("monitoring_settings", gaze_enabled=True)
    → load_config()
    → config["monitoring_settings"].update(...)
    → save_config(...)
    → возвращение итогового dict
```

При повреждённом JSON `update_config()` начинает с defaults и заменяет файл
новой корректной конфигурацией при успешной записи.

## Как добавлять и изменять настройки

### Новый ключ

1. Добавьте ключ и безопасное значение по умолчанию в нужную секцию `DEFAULT_CONFIG`.
2. Сохраняйте его через `update_config("section_name", new_key=value)`.
3. При чтении дополнительно нормализуйте тип в потребляющем модуле.
4. Если ключ влияет на UI, обновите соответствующую страницу документации.

### Изменение типа существующего ключа

Старые файлы могут содержать прежний тип. Добавьте совместимое преобразование
при чтении либо отдельную миграцию до того, как потребитель начнёт использовать
значение.

### Новая секция

Добавьте секцию-словарь в `DEFAULT_CONFIG` и передавайте её имя первым аргументом
`update_config()`. Вложенность глубже уровня секции автоматически не объединяется.

## Текущие ограничения

- Нет централизованной проверки типов, диапазонов и обязательных ключей.
- Неизвестные ключи не удаляются.
- Запись не атомарная: временный файл и последующая замена не используются.
- Нет блокировки при одновременной записи из нескольких потоков или процессов.
- Каждый `update_config()` заново читает и полностью перезаписывает JSON.
- Объекты глубже уровня секции объединяются только целиком.
