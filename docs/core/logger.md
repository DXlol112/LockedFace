# Модуль `logger.py`

## Назначение модуля

`script/core/logger.py` настраивает общую систему logging LockedFace,
ротационные файлы, необязательный вывод в консоль и перенаправление сообщений
Qt.

## Место в архитектуре

`LockedFace.main()` вызывает `setup_logging()` после создания и настройки
`QApplication`. После этого все дочерние loggers распространяют записи в
настроенный root logger.

При необработанном исключении точка входа дополнительно создаёт `crash.log`, но
эта операция находится за пределами данного модуля.

## Константы

### `LOG_FORMAT`

Формат включает время, уровень, имя logger, имя исходного файла, номер строки и
сообщение:

```text
2026-08-30 12:00:00 | INFO     | module | file.py:10 | message
```

### `DATE_FORMAT`

Строка `%Y-%m-%d %H:%M:%S` для времени каждой записи.

## Справочник функций

### `qt_message_handler(mode, context, message) -> None`

Преобразует тип сообщения Qt в соответствующий вызов Python logging.

**Параметры:**

- `mode` — значение `QtMsgType`;
- `context` — контекст Qt; текущая реализация его не использует;
- `message` — текст записи.

**Соответствие уровней:**

| Qt | logging |
| --- | --- |
| `QtDebugMsg` | `debug` |
| `QtInfoMsg` | `info` |
| `QtWarningMsg` | `warning` |
| `QtCriticalMsg` | `error` |
| `QtFatalMsg` | `critical` |

**Возвращаемое значение:** отсутствует.

**Побочные эффекты:** отправляет запись logger с именем `Qt`.

**Важные условия:** неизвестный тип игнорируется. Контекст, категория и место
исходного Qt-сообщения не добавляются отдельно.

### `setup_logging() -> None`

Полностью заменяет handlers root logger и устанавливает обработчик сообщений
Qt.

**Последовательность настройки:**

1. получает и создаёт каталог логов;
2. создаёт общий formatter;
3. устанавливает root level `DEBUG` и очищает прежние handlers;
4. добавляет `app.log`: `DEBUG+`, максимум 5 MiB, три backup-файла;
5. добавляет `error.log`: `ERROR+`, максимум 2 MiB, три backup-файла;
6. если `sys.stdout` доступен, добавляет консольный handler уровня `INFO`;
7. включает перехват `warnings`;
8. ограничивает `py.warnings`, `google` и `mediapipe` уровнем `ERROR`;
9. устанавливает `qt_message_handler` через `qInstallMessageHandler()`;
10. записывает сообщения об успешной инициализации.

**Возвращаемое значение:** отсутствует.

**Побочные эффекты:** создаёт каталоги и файлы, очищает глобальные logging-
handlers, меняет уровни сторонних loggers и глобальный обработчик Qt.

**Исключения:** ошибки создания каталога или `RotatingFileHandler` не
перехватываются.

## Маршрутизация записей

| Уровень | `app.log` | `error.log` | Консоль |
| --- | --- | --- | --- |
| `DEBUG` | Да | Нет | Нет |
| `INFO` | Да | Нет | Да |
| `WARNING` | Да | Нет | Да |
| `ERROR`/`CRITICAL` | Да | Да | Да |

## Как расширять логирование

### Добавить отдельный файл

Создайте handler после formatter, назначьте уровень или filter, установите тот
же formatter и добавьте его к root logger. Учитывайте, что запись может попасть
сразу в несколько файлов.

### Добавить структурный контекст

Передавайте значения через `extra`, используйте `LoggerAdapter` либо filter.
Если поле должно появиться в каждой строке, одновременно обновите
`LOG_FORMAT` и обеспечьте default для всех записей.

### Изменить шум сторонней библиотеки

Настройте уровень именованного logger после `logging.captureWarnings(True)`.
Не повышайте root level, если нужно скрыть только один пакет.

## Текущие ограничения

- Повторный вызов удаляет все handlers, установленные другими компонентами.
- Настройка является глобальной и не возвращает созданные handlers.
- Ошибки файловой системы могут прервать запуск приложения.
- Уровень `ERROR` для MediaPipe и Google скрывает предупреждения библиотек.
- В оконной сборке `sys.stdout` может отсутствовать, поэтому консоли не будет.
- `qt_message_handler()` игнорирует объект `context`.
