# Модуль `path_utils.py`

## Назначение модуля

`script/core/path_utils.py` разделяет ресурсы программы и изменяемые данные
пользователя. Он учитывает запуск из исходников и one-folder сборку, выбирает
каталог данных и создаёт подпапки для логов и медиа.

## Место в архитектуре

Точка входа вызывает `os.chdir(get_application_dir())`, поэтому относительные
пути UI к `static`, `script/style` и `translations` вычисляются от каталога
приложения.

`config.py`, `logger.py` и `FilePage` используют отдельные getters
пользовательских путей.

## Константы

### `PROJECT_DIR`

`Path(__file__).resolve().parents[2]` — корень исходного проекта, вычисленный от
местоположения `script/core/path_utils.py`.

### `DATA_DIR_ENVIRONMENT_VARIABLE`

Строка `"LOCKEDFACE_DATA_DIR"`. Переменная окружения позволяет явно указать
каталог данных для тестирования или портативного запуска.

## Справочник функций

### `get_application_dir() -> Path`

Возвращает каталог, содержащий ресурсы приложения.

**Результат:**

- при `sys.frozen == True` — разрешённый родитель `sys.executable`;
- при обычном запуске — `PROJECT_DIR`.

**Побочные эффекты и исключения:** функция не создаёт каталог и не выполняет
запись; стандартные ошибки преобразования пути обычно не возникают.

### `get_data_dir() -> Path`

Выбирает изменяемый пользовательский каталог и гарантирует его существование.

**Приоритет:**

1. непустое значение `LOCKEDFACE_DATA_DIR`;
2. `QStandardPaths.AppLocalDataLocation`;
3. подпапка `data` внутри каталога приложения, если Qt не вернул путь.

**Возвращаемое значение:** выбранный `Path`.

**Побочные эффекты:** вызывает `mkdir(parents=True, exist_ok=True)`.

**Исключения:** ошибки доступа и создания каталога не перехватываются.

**Важные условия:** значение переменной окружения не нормализуется через
`resolve()` и не раскрывает `~`. Относительный путь остаётся относительным к
текущему рабочему каталогу.

### `get_config_path() -> Path`

Возвращает `get_data_dir() / "config.json"`.

**Побочные эффекты:** базовый каталог создаётся, сам JSON-файл — нет.

### `get_log_dir() -> Path`

Получает каталог данных, создаёт в нём подпапку `log` и возвращает её.

**Побочные эффекты:** файловая операция `mkdir(exist_ok=True)`.

### `get_media_dir() -> Path`

Получает каталог данных, создаёт подпапку `media` и возвращает её.

**Побочные эффекты:** файловая операция `mkdir(exist_ok=True)`.

## Поток выбора путей

```text
get_application_dir()
    ├── source → PROJECT_DIR
    └── frozen → directory of sys.executable

get_data_dir()
    ├── LOCKEDFACE_DATA_DIR
    ├── QStandardPaths.AppLocalDataLocation
    └── application_dir/data
        ├── config.json
        ├── log/
        └── media/
```

## Как добавлять новые каталоги

1. Создайте getter, основанный на `get_data_dir()` для изменяемых данных или на
   `get_application_dir()` для ресурсов только для чтения.
2. Для изменяемого каталога вызовите `mkdir()` и верните `Path`.
3. Не сохраняйте пользовательские файлы рядом с исходниками или exe без явной
   причины.
4. Экспортируйте публичный getter из `script/core/__init__.py` и `script`, если
   он нужен UI.

## Текущие ограничения

- Getters каталогов одновременно вычисляют путь и изменяют файловую систему.
- Переменная окружения не проверяется на абсолютность и доступность.
- Fallback `application_dir/data` может оказаться недоступен для записи.
- Корректность относительных путей ресурсов зависит от `chdir()` в точке входа.
- Создание каталогов не оборачивается в собственные сообщения об ошибках.
