# UI-слой LockedFace

## Назначение документации

Этот раздел описывает графический интерфейс LockedFace, расположенный в
`script/UI`, и вспомогательные виджеты из `script/UI/support_UI`. Каждому
Python-модулю, содержащему классы, соответствует отдельная страница.

Документация отражает текущее поведение кода. Модули `script/core` и
`script/core/monitoring` рассматриваются только как зависимости UI.

## Карта модулей

| Исходный модуль | Документация | Назначение |
| --- | --- | --- |
| `script/UI/start_page.py` | [Стартовая страница](start_page.md) | Инструкция перед началом работы |
| `script/UI/main_page.py` | [Главная страница](main_page.md) | Таймер и управление мониторингом |
| `script/UI/settings_page.py` | [Страница настроек](settings_page.md) | Настройки, язык, версия и внешние действия |
| `script/UI/file_page.py` | [Страница файлов](file_page.md) | Добавление, выбор и удаление медиа |

## Место UI в приложении

Точка входа `LockedFace.py` создаёт `MainWindow` и помещает четыре страницы в
`QStackedWidget`. Страницы не знают о главном окне напрямую: переходы передаются
им как callbacks при создании.

```text
MainWindow
├── StartPage(on_continue=go_to_main)
├── MainPage(
│   on_start=start_program,
│   on_settings=go_to_settings,
│   on_file=go_to_file,
│   )
├── SettingsPage(on_back=go_back)
└── FilePage(on_back=go_back)
    └── FileCard(on_click=select_file)
```

Такое устройство разделяет построение виджетов и навигацию. Страница вызывает
переданный callback, а `MainWindow` решает, какой виджет показать.

## Общий поток работы

1. `StartPage` показывает рекомендации по расположению камеры.
2. После нажатия кнопки `MainWindow` показывает `MainPage`.
3. Из `MainPage` пользователь может перейти к файлам или настройкам.
4. `FilePage` копирует выбранное медиа в управляемый каталог приложения и
   сохраняет путь через `update_config()`.
5. `SettingsPage` сохраняет переключатели и язык через тот же механизм
   конфигурации.
6. `MainPage` проверяет камеру, файл и продолжительность, после чего запускает
   `VideoThread`.
7. `VideoThread` передаёт кадры сигналом `change_pixmap_signal`, а UI отображает
   их в `QLabel`. Сигнал `finished_signal` возвращает страницу к таймеру.

## Callbacks и сигналы

### Навигационные callbacks

Callbacks создают слабую связанность между страницами и `MainWindow`. Текущий
код ожидает функции без аргументов. Исключение — callback карточки файла:
`FileCard` передаёт ему путь выбранного медиа.

| Компонент | Callback | Когда вызывается |
| --- | --- | --- |
| `StartPage` | `on_continue()` | Нажата кнопка продолжения |
| `MainPage` | `on_settings()` | Открываются настройки |
| `MainPage` | `on_file()` | Открывается галерея файлов |
| `MainPage` | `on_start_callback()` | Поток мониторинга уже создан и запущен |
| `SettingsPage` | `on_back()` | Нажата кнопка возврата |
| `FilePage` | `on_back()` | Нажата кнопка возврата |
| `FileCard` | `on_click(path)` | Карточка нажата левой кнопкой мыши |

### Сигналы Qt

UI активно использует стандартные сигналы `clicked`, `toggled`,
`currentTextChanged`, `mediaStatusChanged`, `durationChanged` и
`videoFrameChanged`. Для обмена с рабочим потоком используются два сигнала
`VideoThread`:

- `change_pixmap_signal(np.ndarray)` передаёт кадр камеры в главный поток UI;
- `finished_signal()` сообщает о завершении мониторинга.

Виджеты должны изменяться только в главном потоке Qt. Поэтому `VideoThread` не
обращается к ним напрямую, а отправляет сигналы.

## Экспорты пакетов

### `script/UI/__init__.py`

Пакет экспортирует:

- `StartPage`;
- `MainPage`;
- `SettingsPage`;
- `FilePage`;
- `WinDialog`.

Благодаря этому точка входа может импортировать страницы через пакет, не зная
внутренние имена модулей.

### `script/UI/support_UI/__init__.py`

Вспомогательный пакет экспортирует `FileCard` и `WinDialog`. Класс
`WrappingPushButton` остаётся внутренней деталью `win_dialog.py` и напрямую из
пакета не экспортируется.

## Конфигурация, которую использует UI

| Ключ | UI-компонент | Назначение |
| --- | --- | --- |
| `selected_file` | `FilePage`, `MainPage` | Абсолютный путь выбранного управляемого медиа |
| `gaze_enabled` | `SettingsPage`, `MainPage` | Включение проверки состояния глаз |
| `glasses_enabled` | `SettingsPage`, `MainPage` | Выбор более мягкого порога для очков |
| `work_time_seconds` | `MainPage` | Продолжительность текущих и будущих сессий |
| `translations_select` | `SettingsPage` | Код языка `RU` или `EN` |

Чтение выполняется через `load_config()`, а частичное обновление — через
`update_config()`. UI не работает с JSON-файлом напрямую.

## Переводы интерфейса

Пользовательские строки передаются через `self.tr(...)`. Виджеты, текст которых
может изменяться после запуска, реализуют `retranslate_ui()` и реагируют на
`QEvent.Type.LanguageChange` в `changeEvent()`.

При добавлении текста необходимо:

1. обернуть строку в `self.tr(...)`;
2. присваивать динамически переводимый текст в `retranslate_ui()`;
3. обновить каталог переводов по существующей инструкции проекта.

## Стили UI

Основные страницы оформляются QSS-файлами из `script/style`, которые точка
входа объединяет в одну таблицу стилей. Стили вспомогательных модулей находятся
в `script/style/QSS_support_UI`; диалог загружает свой QSS самостоятельно.
Связь кода со стилями задаётся прежде всего через
`setObjectName()`.

При переименовании `objectName` нужно найти соответствующий QSS-селектор.
Подробный справочник CSS-свойств в эту документацию не входит.

## Добавление нового UI-модуля

1. Создайте модуль в `script/UI` или `script/UI/support_UI`.
2. Реализуйте виджет и явно определите его входные callbacks.
3. Для новой страницы добавьте экспорт в `script/UI/__init__.py` и регистрацию
   в `MainWindow.stack`.
4. Переводимые строки вынесите в `retranslate_ui()`.
5. При необходимости добавьте QSS-селекторы для новых `objectName`.
6. Создайте отдельную страницу в `docs/ui` и добавьте её в карту модулей выше.

## Текущие ограничения UI-слоя

- Главное окно имеет фиксированный размер `800 × 600`.
- Типы callbacks не формализованы через `Protocol` или отдельные алиасы.
- Некоторые длительные операции, например проверка обновлений и первичная
  проверка камеры, запускаются из главного UI-потока.
- Содержимое страниц создаётся программно; `.ui`-файлы Qt Designer не
  используются.
- Структура QSS зависит от строковых `objectName`, поэтому их переименование
  требует синхронного изменения стилей.
